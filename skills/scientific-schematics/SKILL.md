# Scientific Schematics

Use this skill for conceptual or structural visuals, not for empirical data plots. Before drawing, define the concept, audience, labels, relationships, output format, and whether the image is a schematic, architecture, workflow, or illustrative asset.

Prefer Mermaid, SVG, matplotlib, MATLAB, TikZ, or another editable path when the diagram is structural and the environment supports it. When an illustrative raster materially improves the explanation, prefer Codex's built-in official `image_gen`; use an external image plugin only when the user selects it or needs its specific capability. Keep exact labels, equations, topology, and evidence-bearing geometry in editable/vector or source-data tools rather than generated bitmaps.

Keep labels, arrows, units, and hierarchy readable at the final size. Avoid invented product internals or unverified mechanisms. Label generalized structures as conceptual or schematic when they are not sourced product facts.

Inspect the final rendered file for clipping, text, contrast, alignment, and legibility. Do not add automatic Git logs, quality reports, iteration histories, or tool traces to a formal deliverable unless explicitly requested.
