# Markdown and Mermaid

Use Markdown for working notes, readmes, and process explanations. Add Mermaid when it makes a relationship, flow, sequence, state machine, or architecture easier to read and maintain. Prose or a table is preferable when the relationship is small or the diagram would add noise.

Choose a diagram type that matches the structure. Keep labels short, accessible, and readable in the target Markdown renderer. Provide a brief textual explanation when the diagram alone is not sufficient.

Do not make Mermaid a mandatory first phase for every document. Do not use it as a substitute for empirical plots, mathematical figures, CAD, or publication-quality multi-panel graphics. Keep the Markdown source and any rendered preview only when useful to the requested output.
