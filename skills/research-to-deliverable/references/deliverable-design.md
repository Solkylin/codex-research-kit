# 交付物设计

## 先确定读者要使用什么

采用用户指定文体和模板。缺少模板时，按读者任务选择结构，而不是套用统一长报告。技术报告围绕问题、方法、结果及含义；数学成果保留定义、论证与应用；演示围绕完整工程问题或核心信息组织；表格服务于比较、计算或操作。

多种格式共用一致的技术内容、数据和术语，再分别组织表达。报告、演示和操作材料不互相机械粘贴；纯分析、代码或模型任务不自动增加正式长文档。

## 学习范例与验证代表样稿

新领域、新工具链、大批量制作或整体改版前，先查看现有成果和用户参考，再按需要检索相似的成熟案例。比较目标读者、任务、证据、信息密度和使用环境，提取有用方法，不复制范例中的缺陷或与当前用途不符的装饰。

先验证能暴露主要难点的少量样稿，例如原图和标注、公式、长表、结构过程或结果图。检查实际渲染和编辑能力，修复具体问题后再推广；数量按难点决定，不固定八页或某种页型。已有批准样式直接复用，内部验样通过后推进；重大取舍或用户明确要求时再等确认。

字体、配色、页脚、表格样式、页数和时长属于项目选择。科研图的坐标、单位、数据与图像完整性可通用；期刊印刷字号不能直接作为投影阅读标准。

## 内容与表达

正文为独立读者而写，直接进入主题。方法、实验步骤、证明、引用、适用条件、误差和复现说明按用途保留；工具日志、分工、进度、自我评价和对话历史留在正文之外。

使用具体专业陈述，删除不帮助读者判断的制作语言、身份表述和泛化免责。真实的模型身份、条件、误差和反例放在对应方法或结论附近；措辞优化不能提升证据强度。

结果身份优先用方法说明，例如“由解析式计算”“基于某模型仿真”“在某工况测得”。方法和对象已经清楚时，不在正文或页脚反复添加“非实测”“不代表实验”“不包含设备辨识”等防御性说明；保留真正影响结论的适用条件、误差、失败和反例。

| 情形 | 面向读者的表达 |
| --- | --- |
| 模型结果与实测 | 说明输入、方法和结果身份，不将一种证据替代另一种。 |
| 通用关系与具体产品 | 原理图明确其对象，产品事实由相应来源支持。 |
| 参数或适用条件 | 保留定义、范围、单位及影响，不填似真的数值。 |
| 多来源比较 | 标明对象、版本、工况和评价条件，不以并置图表代替因果论证。 |
| 反例或负面结果 | 保留结果、代价及其对判断的影响。 |

## 知识承接与配套一致性

合并、拆分、精简或跨格式改编时，核对关键对象、机制、条件、公式、数据、案例和证据在新载体中的实际去向。修正旧错误、合并重复或撤下无关内容应有明确理由；旧标题、页数或身份仍存在，不等于知识保全。明显的大规模重构才建立必要的承接表，小修不另造台账。

从当前有效主稿核对其他成品：正文、图注、备注、来源范围、讲稿、目录、索引和引用必须相容。不要整段继承旧版来源清单、对象标签或指图说明。原始谱系可留在工作区，读者入口应指向当前有效文件，不依赖缺失的旧版本。

## 检查真实文件

使用目标格式的专业skill、成熟工具和适用模板。保留需要的可编辑源文件，精确技术图形优先采用可复现数据或矢量路径；更多图组方法见[技术演示](document-to-presentation.md)。

- 文档和演示：新制作检查各页实际渲染，局部修改复看受影响页面及分页连带变化；检查中文、公式、图表、裁切、遮挡和阅读顺序。
- 表格：核对关键公式、引用、单位、格式、行高和显示；具备重算能力时核对重算结果。
- 代码和计算：运行对应入口或最小有效用例，检查实际输出与正文结论相符。
- 动态或交互材料：实际播放／操作与静态输出分别验证；未运行时不声称行为通过。

对象存在不证明可见或可读，脚本成功不证明文件可用，静态检查也不证明数值复现、仿真或实机行为。记录实际覆盖范围，缺失材料下的判断限定范围；不能比较旧稿时，不宣称已证明旧版知识完全无损。

已有检查在输入、实现和环境未变时按其适用范围复用。用户明确指定多轮复核时执行；否则不预设轮次，也不把增加哈希或重复检查当作质量本身。

## 交付范围

成品目录只包含所需正式文件与必要附件；按清单选取文件打包，不把工作目录整体发送。必要代码、数据和环境说明按用户用途提供，原始资料集中库可与使用包分离。

交付前核对占位符、失效引用、编辑批注、过程性文字和重复成品；修复实际文件并复查变化。需要离线或独立使用时，从交付包实际打开并检查必要资源是否随包或已嵌入。恢复工作的方法见[续接与上下文](continuity.md)。
