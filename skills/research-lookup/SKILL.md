# Research Lookup

围绕本次需要成立的结论检索，优先原始论文、官方文档、标准发布方、厂商资料和作者仓库。先利用相关现有材料；必要时补充外部来源。

## 选择可用能力

先看当前工具清单；存在延迟加载入口时按任务检索所需能力。可用工具不一定附带 skill，也不因缓存中存在插件文件就视为能调用。

| 当前需要 | 候选能力 |
|---|---|
| 当前事实、官方网页、技术文档 | 原生网络检索，或已可调用的 Parallel、Exa、Firecrawl |
| 论文、作者、引用链或候选文献 | Consensus、SciSpace、Firecrawl 论文工具、公开学术数据库；已有 `paper-lookup` 也可使用 |
| 多步深入文献研究 | 已可用的 Undermind 或其他适用研究工具；普通检索不启动长任务 |
| 个人库和已有引用 | 项目书目文件、Zotero/Better BibTeX、`pyzotero`；引用整理再用 `citation-management` |
| 项目已有 CLI/API 流程 | 已安装且可用的 Parallel CLI 或本 skill 的历史脚本；服从项目环境与用户选择 |

优先能完成任务的现有路径。缺少某品牌 CLI 或其密钥时，直接改用可用的网络/学术工具，不为普通检索自动安装、索取密钥或重复认证。用户明确指定后端时优先遵循；必要连接失败就说明具体限制并推进独立部分。

使用连接器前遵循其当前工具契约。例如 Consensus 结果须按其要求获取论文记录后引用，Undermind 先使用其可用的引导入口；不要凭旧教程猜测参数。异步检索跟踪到完成、失败或确需用户处理，不把启动任务当作已经取得结论。

## 检索与证据

1. 从问题提取主题、对象、方法、工况、时间和关键术语。用少量有区分力的查询；多个独立方向有收益时批量或并行。
2. 按主题匹配、方法适用性、证据质量和日期选择材料。被引数和期刊声誉只是补充线索，不用固定影响因子或被引阈值排除重要的小领域、新研究或负面结果。
3. 搜索摘要用于定位。决定结论的公式、数据、表格、定义和比较条件回查实际正文；没有全文时限定为已读到的内容。
4. 核对事件日期、发表日期、版本和适用条件。区分同行评审论文、预印本、综述与厂商陈述；不把并置结果当因果证据。
5. 来源冲突时定位争点并做针对性查询；材料已足以回答关键问题时转入综合，不固定要求两轮搜索、固定篇数或全部数据库。
6. 普通综述按主题综合；系统综述、范围综述或元分析按明确任务加载 `literature-review` 的相应方法。

只向公开检索服务提交可公开的查询。内部文件需保持在已授权范围，采用本地提取或已批准的服务，不因检索方便而上传原件。

## 来源保存与交付

保留支持结论的标题、作者或机构、日期、URL/DOI及必要页码。来源放在对应事实附近；不编造 DOI、作者、页码或未读取的引文。

长任务、批量文献综合、复现要求或用户要求留档时，复用项目已有 `sources/` 或工作区，保存必要的来源与检索范围。简单查询可直接在回答中引用，不为每次调用生成原始 JSON、时间戳日志或新的审计目录。已保存材料在仍适用时复用。

交付研究结论、必要解释、来源和影响判断的条件；工具日志、后端调度和存档操作不进入正式正文。检索本身不触发插图、AI 图像或示意图生成。

## 历史脚本的兼容使用

本目录保留 `scripts/` 及根目录的兼容入口。只有项目已采用这些脚本或当前工具不足时才使用，先以实际脚本的 `--help` 与代码确认参数和依赖。

`scripts/research_lookup.py` 的旧后端可能需要 `PARALLEL_API_KEY` 或 `OPENROUTER_API_KEY`；只检查是否已配置，读取与传递时不打印密钥。脚本内部的固定后端、输出和错误处理仅约束该脚本运行，不是其他网络工具的调用规则。脚本不能满足当前任务时改用可用能力，或修复项目授权范围内的实际问题。
