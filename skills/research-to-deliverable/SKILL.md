# Research to Deliverable

将问题推进为有依据、可使用、适合目标读者的结果。按任务选择方法，不把全部参考文件和固定流程加载到每次工作中。

## 确定结果与有效输入

从当前请求、用户材料和项目约定确定目标、读者、输入范围、结果形式及可判断的完成条件。先读取相关现有成果；延续任务先辨认有效版本与已定决策。只为无法自行取得且实质影响结果的信息提问。

当前只需局部处理时直接完成。长任务按[续接与上下文](references/continuity.md)维护简短状态，复用已有有效记录；不为普通任务另造计划、台账或审计包。

## 按需加载方法

涉及专业研究、计算、实现或文件制作时，先快速核对[技能路由](references/skill-routing.md)与当前可用能力，再由本主流程显式读取本阶段需要的支持 skill 和方法。`technical-presentations`、`publication-figures`、`docling` 等支持 skill 不单独隐式编排；进入新的工作阶段或遇到工具阻碍时补选路线；简单问答和局部修改无需执行这一步。

| 当前任务 | 读取的参考 |
| --- | --- |
| 文献、事实、来源冲突与证据综合 | [研究与计算](references/research-and-computation.md) |
| 定义、推导、量纲、模型与数学条件 | [数学建模](references/mathematical-modeling.md) |
| 数据、数值实验、仿真与资源选择 | [计算实验](references/computational-experiment.md) |
| 能独立推进并提高质量的工作流 | [并行协作](references/parallel-work.md) |
| 正式成果、样稿验证或多格式交付 | [交付物设计](references/deliverable-design.md) |
| 文献原图、复杂版面与资料提取 | [资料到演示的工具入口](references/document-to-presentation.md) |
| 科研数据图、多面板图与交互精修 | [出版级科研绘图](references/publication-figures.md)，由 `publication-figures` 按需选择对象编辑或矢量排版路线 |

只读取会改变当前决策的参考。先选择能完成任务的能力，再加载最窄且适用的专业skill；没有配套skill的可调用工具也可直接使用。使用专业skill前先读其`SKILL.md`；相近替代路线不同时加载。专业skill负责领域与格式，本入口负责选路、共同前提及最终整合。

涉及明确专业领域或成品格式时，优先读取并遵循当前可用的专用 skill，再调用其适配工具；不要只凭通用流程重写专业方法。图片任务优先当前会话可用的 Codex 内置官方 `image_gen`，由 `imagegen` 提供调用和文件保存规则；若该工具未暴露，才根据任务特性选择已连接的专用图像插件，CLI/API fallback 仅在用户明确选择后使用。技术演示显式读取 [technical-presentations](../technical-presentations/SKILL.md) 组织证据、页面与讲稿，由 `pptx`/PowerPoint 或目标平台工具制作与渲染。实证数据图用源数据和绘图软件生成，生成式图像只用于适合的插图、背景或概念素材。

把本次需要的证据、推导／计算、编辑方式、输出文件和成品检查对应到实际能力；选路应落实为工具操作与可检查结果。工具名称出现在方案中、skill已经读取或脚本已经启动，都不表示该部分工作完成。局部任务可以只使用其中一项能力。

## 获取依据并完成核心工作

优先解决会改变结论的事实、假设和计算。外部检索优先一手原文；摘要和解析结果用于定位，关键图、表、公式和动作仍回查原件。区分来源事实、推导、假设、数值结果与实测。

新领域、新工具链或大型交付先研究用途相近的成熟范例；按读者、任务、证据和使用环境判断可借鉴之处。已有可靠方案直接复用，不为小修重复检索。

复用成熟实现及用户认可的方法。工具和插件按当前可见能力自主选择；安装、认证和实际调用不是同一状态。可选能力缺失时使用可行替代，不假定工具存在，也不因工具可用而扩大授权或任务范围。新增依赖先判断收益、来源、许可与副作用，必要时隔离试用，不覆盖本地定制技能。

存在独立工作流时明确输入、输出、权限和完成条件，按收益并行。主任务推进其他工作并整合实际证据，不重复全部调查，也不用多个相同答案代替验证。

## 验证、交付与停止

按主要错误模式检查实际结果：研究核对来源支持，数学核对前提与关键性质，实现核对对应行为，文件核对真实渲染与使用。区分静态、数值、仿真和实机证据，不把不能覆盖的性质称为已验证。

新工具链、大批量制作或整体改版前验证代表难点；重构时按知识单元承接；跨格式输出分别组织并核对一致性，具体方法见交付参考。已有有效结果按适用范围复用，新变化或具体疑点才扩大检查；不默认固定复核次数、哈希或全量测试。

发现问题修复实际主稿并复查受影响内容。确认错误、待证疑点与可选增强分别处理；不为凑问题或增加研究而延后已满足要求的交付。

按指定位置交付所需成品与必要源文件。正文保留理解、判断和复现需要的内容；工作状态、协作过程和日志留在成品之外。说明结果、使用入口与实际验证范围，不声称未完成的检查。

交付前确认本次完成标准中的关键处理已经实际执行；尚缺资料获取、可编辑修改、求解、重算、导出或渲染时，继续完成对应环节，不把它们降为可选建议。已满足目标的结果不因尚有其他品牌或替代工具可试而延后交付；确有阻碍时给出具体受阻环节与已完成产物。
